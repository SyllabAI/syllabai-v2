## Security posture (why this cannot leak)

- No auth bypass exists: the demo session IS a normal login (same
  AuthController/v2 endpoint, same JWT, same RBAC). Every dashboard call
  rides the demo account's own bearer token exactly as any user's would.
- Credentials live in ONE server-only module ("server-only" imported;
  never in a client bundle; import graph verified: the client landing
  does not import it). Env-var names are pre-wired for the removal round.
- The route answers 404 the moment SHOWCASE_DEMO_ENABLED=false — one line
  turns the whole showcase off; full removal deletes 4 files + the graft.

# ADDENDUM (same run) — ops of record correction + the P30D incident

**Correction:** the shipped env value is `SYLLABAI_JWT_TTL=PT720H` (parseable:
720h × 3600 = 2,592,000s = 30 days). The run-001 body above said `P30D` — that
value is UNSAFE: `parseIsoDuration` (apps/api/src/services/identity/jwt.ts:73)
accepts only the `PT[nH][nM][nS]` subset and THROWS on any other form, which
crashes JwtService construction and takes every API invocation down with it.

**Incident of record:** setting `P30D` 500'd the API carrier for ≈45 min
(≈20:15–21:00 UTC, 2026-11-04). Runtime env flows to deployments created after
the change; the recovery alias first landed on `dpl_4KZd` — an unverified
`target=None` build that 500s independently. Resolved by re-aliasing
production to the operator's own working `dpl_7Q3C` (CLI-deployed 20:08),
correcting the env to `PT720H`, redeploying from `dpl_7Q3C` as `dpl_3N7w1T`
(READY, auto-aliased), and deleting the broken `dpl_FXdsh`.

**Live verification of record (production, post-fix):**
- student + teacher demo logins: `ttl=2592000s` (30 days), roles STUDENT/TEACHER
- hub `dpl_GV9Suo6` (main `d9d95faa`): `/` + `/demo` render the showcase landing
- `/api/demo/login?role=student|teacher` → 200 real sessions; `?role=admin` → 400
- `/dashboard` without cookie → 307 `/login?next=…`; with student cookie → 200
- student cookie on `/teacher` → 307 `/dashboard` (isolation law intact)
- signed-in session on `/` → 307 role home (the "perpetually logged in" behavior)

**Lesson for every lane:** `SYLLABAI_JWT_TTL` is PT-form ONLY. Never `P30D`.
