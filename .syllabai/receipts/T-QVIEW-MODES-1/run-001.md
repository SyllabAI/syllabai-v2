## THE ORDER

The operator wants two view modes for the question player (both surfaces render the shared `QuestionPlayer`): mode 1 — only ONE question on the page at a time, navigated by the question-number grid at the top and Previous/Next buttons at the bottom; mode 2 — the current all-questions-on-one-page scroll. The plan was presented first (per the operator's "Tell me your plan first") with three decision points; the operator replied "Agree" — locking: default = "all" on both surfaces, toggle above the grid, endpoints disabled (no wrap).

## THE CHANGE (1 file, zero new lib logic)

- **External store for the persisted mode** (module level): `VIEW_MODE_STORAGE_KEY = "syllabai-player-viewmode"`, `type ViewMode = "all" | "single"`; `subscribeViewMode` (explicit same-tab listener ping on write + the `storage` event for other tabs), `getViewModeSnapshot` (fail-closed: anything but "single" reads as "all"), `getServerViewModeSnapshot` (pinned "all" — hydration truth), `writeViewMode` (try/catch tolerant write + listener ping). The component consumes it through `useSyncExternalStore` — SSR and first paint always render "all", so there is no hydration mismatch, and the stored choice lands right after hydration.
- **Derived truth, no state duplication**: `viewIdx` — the question the player is actually on — is `activeIdx` clamped into the visible list in single mode (`Math.max(0, Math.min(activeIdx ?? 0, visible.length - 1))`, which also guards empty sets), passthrough in "all" where the IntersectionObserver scroll-spy owns it. Every consumer that means "the question in view" now reads `viewIdx`: the grid's `aria-current` + active ring, the single-card map gate, the pagination counter, the CLA anchor resolution (`claAnchorIdx`) and the floating button's aria/title disclosure.
- **Single mode mechanics**: the map renders exactly one card of the SAME list (`single && qi !== viewIdx ? null : …` — same keys, same real index `qi`, so printed paper numbers (batch A), CLA anchoring, full-screen and mark-scheme targets are all unchanged); the scroll-spy effect early-returns (`single` in guard + deps) because one card is always in view; `goTo(i)` swaps the card and lands at the top of the page (reduced-motion aware via `scrollBehavior()`) instead of anchor-scrolling; the toggle choreography lands at the top entering single and restores the question being read when returning to "all" (post-commit `setTimeout`).
- **Pagination footer** (single mode only, `nav aria-label="Question pagination"`): `← Previous` | `Question {qLabel(viewIdx)} of {visible.length}` | `Next →` — outline Buttons, chevron icons, endpoints DISABLED (a paper has ends; it does not wrap), counter `aria-live="polite"`, `aria-keyshortcuts` mirroring the keyboard stepping.
- **Keyboard**: ←/→ step through questions in single mode only, and never while typing (INPUT/TEXTAREA/SELECT/contentEditable), inside a dialog/overlay (`[role="dialog"]`) or on the difficulty tablist (`[role="tablist"]` — its arrows mean tabs).
- **The toggle**: a compact pill (`role="group" aria-label="View mode"`) above the question-number grid on BOTH surfaces — "All on one page" / "One at a time", `aria-pressed` states, same visual language as the difficulty tabs (bg-primary/10 active).
- **Mode interplay**: bank mode's difficulty filter works inside single mode — changing the filter re-derives `viewIdx` against the new visible list (clamped), so no out-of-range state can render; paper mode has no filter, so its single mode is fully stable.
