## Verdict

FIX IMPLEMENTED AT THE RENDER LAYER (apps/hub) — corpus untouched. The hub
SSRs raw `bodyMd` through react-markdown per request (the RSC payload
carries the raw markdown; the corpus .md files are only the import source),
so a pre-pass in `apps/hub/src/lib` fixes every live page with zero data
migration, and future corpus imports inherit the fix automatically.

## Changes

- `apps/hub/src/lib/emphasis-fix.ts` — v2 rewrite (replaces the
  2026-09-19 pass). Three corpus-confirmed defects of the old pass:
  1. paragraph scope: it split only on blank lines, so consecutive list
     items formed one "paragraph" and its CommonMark-claim pass paired an
     opener in one bullet with a closer two bullets later, then the greedy
     leftover repair boxed literal `**` inside a bogus `<strong>`;
  2. single-run early return (`runs.length < 2`): lone strays
     (`=$A$1+B2**"`, `10**<sup> -3`, `****an allele`) never cleaned;
  3. active harm: leftover pairing rewrote VALID cells
     (`| **\$** |` → `| \$** |`).
  v2: CommonMark-block-scoped units (blank lines, list markers at ANY
  indent — nested bullets live at 4 spaces here — headings, blockquotes,
  table rows, fences), a delimiter-stack simulation (flanking §6.2, odd
  rule, openers_bottom) deciding which runs actually RENDER, and repairs
  only on runs proven unrendered: whitespace-in-marker trim (space moved
  OUTSIDE the delimiters against non-whitespace neighbours), partial-run
  shrink, stray deletion (digit-flanked `2**3` is content and stays),
  per-cell repair inside table rows. Math/code protection uses the hub's
  own math-fix delimiter laws (`(?<!\\)\$…` — an escaped `\$` is NOT a
  span opener; the naive rule shielded the opener of `**\$90 000**` and
  let the stray-deleter eat its closer, manufacturing a leak on a page
  that rendered clean).
- `apps/hub/src/lib/table-fix.ts` — NEW. `<br>`-glued row split (only at
  row boundaries — `<br>` inside cell text is formatting and stays),
  prose-glued header split when the delimiter row follows (N3, indent
  preserved), blank-line insertion (GFM tables cannot interrupt a
  paragraph), and escaped nested-table unwrap (N2b: any cell carrying
  `\|` + `<br>` glue — the upstream flattened table-in-a-table-cell —
  outer row keeps its real cells with the nested cell shrunk to its prose
  prefix; the inner table re-emits as a real table after the outer one
  ends, buffered and blank-separated).
- `apps/hub/src/components/markdown.tsx` — wires the pipeline in the order
  tables → emphasis → math (the order the corpus validators mirror).
- `apps/hub/src/lib/__tests__/emphasis-fix.test.ts` (17 cases),
  `apps/hub/src/lib/__tests__/table-fix.test.ts` (9 cases) — every case is
  a real corpus shape with its source file noted. Dependency-free; run
  standalone: `bun test src/lib/__tests__/emphasis-fix.test.ts
  src/lib/__tests__/table-fix.test.ts` → 26 pass / 0 fail.

No-harm gate (the acceptance law): every file with ZERO raw leaks must
render unchanged — visible text compared with `*`/`|` markers stripped
(repairs only ever REMOVE unrendered markers); a manufactured leak (new
`**`/pipe-delim on a previously clean page) is a violation. Result: **0
violations across 9,153 files**.

Live-page mapping: the QA scanned 6,293 unique pages; the corpus carries
9,153 files (duplicated notes across courses), so the 27-file residual
maps to ≈20 live pages — down from 1,447 (98.6%).

Known residue (26 files + 5 table pages, listed in
`run-001-residual-leak-files.txt`): deep `***…**…***` mixed-slop chains
(italics interlaced with bold junk) where the delimiter-stack simulation
and micromark diverge on multi-consume binding. A single-bind-per-closer
repair variant was TESTED and REJECTED by the no-harm gate: it closed ~56
more hit instances but mis-shrunk valid `***x***` sandwiches (4 no-harm
violations, e.g. sketching-gradient-functions.md) — reverted. These 27
files need either a byte-exact CommonMark oracle in the pre-pass or
corpus-side cleanup; neither is in this ticket's scope.

## Disclosures

- The validator skips `<code>`/`<pre>` and KaTeX-rendered spans in the
  visible-text extraction (a learner sees KaTeX output, not the TeX
  source; `2**3` inside code is content). The QA sweep's SSR-based
  detector worked the same way (MON-2 class).
- `bun install` at repo HEAD fails in a clean checkout
  (`@syllabai/editor-gates` / `@syllabai/shared` workspace:* — the
  `packages/*` directory is absent at this commit). PRE-EXISTING, not
  touched by this branch. The new lib tests are dependency-free and ran
  standalone; `ugm.render.test.ts` and `typecheck` need the workspace
  install and must be judged by CI.
- Idempotence: the pipeline is deterministic per render; the table-fix
  pass is idempotent (pinned by test).
