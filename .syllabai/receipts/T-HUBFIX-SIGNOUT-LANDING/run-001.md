## The change

`apps/hub/src/components/layout/app-shell.tsx` — the ONE "Sign out"
DropdownMenuItem (the top-right identity dropdown; pinned as the only sign-out
surface by grep of record: `clearIdentity` has exactly one caller in hub src):

- before: `onClick={() => clearIdentity()}` — the session cleared, no
  navigation; the route gate (`apps/hub/src/proxy.ts:73` →
  `url.pathname = "/login"`) then bounced the next gated-route round trip to
  `/login`, so a sign-out on `/teacher`, `/learner` or `/dashboard` landed on
  the login page.
- after: `clearIdentity(); window.location.assign("/")` — the session clears,
  then a HARD navigation (not `router.push`) to `/`, which sits outside the
  gate policy (`lib/route-gate.ts`: "`/` and `/login` sit outside the policy")
  and, signed out, renders the showcase landing
  (`components/demo/showcase-landing.tsx` via `app/page.tsx`).

The hard-assign is the SAME law as the sign-in fix (T-HUBFIX-SIGNIN-NAV-RACE):
`clearIdentity()` fires the identity event and the shell re-renders signed-out
in place; an in-app redirect would race the gate's 307 on gated routes. A full
assign is one clean round trip, no race, no bounce.

## RUN-002 (live verification caught it) — the assign must AWAIT the cookie unmirror

Live verification of run-001 on the deployed hub (agent-browser, deployment
sha 97f7d818) FAILED honestly: Sign out → token GONE (clearIdentity ran) but
the browser landed on `/dashboard`, not `/`. Diagnosis of record:

- `clearSession()` (lib/api.ts:1052) unmirrors the routing cookie as
  `void unmirrorRoutingSession()` — a FIRE-AND-FORGET DELETE /api/session.
- run-001's handler navigated (`window.location.assign("/")`) without waiting,
  so the stale `sai_session` cookie rode the GET / (cookie presence POST-
  sign-out captured live: `sai_session=eyJ…` still in the jar), and the
  proxy's role-home redirect (`roleHomeRedirect`) bounced the fresh sign-out
  to /dashboard. The gate also explains `/`→/dashboard for a signed-in
  identity — the A-2 server-half law — but here the identity was ALREADY
  signed out client-side; only the cookie mirror lied.
- FIX: the handler awaits the unmirror before the assign —
  `clearIdentity(); await unmirrorRoutingSession(); window.location.assign("/")`.
  `unmirrorRoutingSession` is best-effort BY DESIGN (it catches its own
  network errors — a blip degrades to the old bounce, never a hang). Import
  direction respected: session-cookie.ts imports nothing from api/identity.
- Gates: hub tsc CLEAN; eslint app-shell CLEAN (same worktree).
