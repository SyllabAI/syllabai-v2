## The four steals that landed (and the two that honestly didn't)

1. **Marks-weighted verb-first submit** (`question-player.tsx`): the
   core-flow draft-phase button read "Submit answers"; it now reads
   **"Submit · N marks"** (totalMarks-aware, singular-safe) — MG's
   "1⚡ Grade answer" law: the action carries the stake it fires for.
   The "then Smart Mark marks every part against the mark scheme"
   caption is untouched (one advisory-ness statement, #863 law).
2. **Non-occluding scheme drawer** (`question-player.tsx` + additive
   `overlayClassName` in `ui/sheet.tsx`): MarkSchemeDialog rendered a
   centered `sm:max-w-4xl` Dialog covering the page; it now renders a
   right **Sheet** — full-bleed on phones (the drawer idiom), 36rem at
   sm, 42rem at lg — so the question card stays visible beside the
   open scheme. The default Sheet overlay (50% black) dimmed the
   question; the new `overlayClassName` prop (additive, default
   unchanged for every existing caller) lets this drawer pass
   `bg-black/10`. Radix behavior (outside-click close, Esc, focus trap,
   aria-modal) is untouched — only the paint changes.
3. **Blur-teaser model answer** (same file): the block under "The
   completed answer should show:" rendered plainly; it now waits behind
   ONE verb-first **"Reveal the completed answer"** button unless the
   learner has saved a self-score for the question
   (`progress.selfScores[question.id]` — the store of record). The
   MARKING POINTS and the typed-answer block render ungated either way
   — the dialog's own law ("compare it with the marking points — award
   yourself the marks you clearly earned") is untouched; only the model
   answer is gated. The teaser is clipped (max-h-36), blurred 5px,
   select-none, pointer-events-none, aria-hidden, with the long-restate
   gradient idiom at the cut. MCQs auto-record a self-score on answer,
   so an answered MCQ's "View answer" is never blurred; an UNANSWERED
   MCQ's is — one deliberate click, MG's exact friction, protecting the
   attempt. Ride-along fix disclosed: `expanded` (the long-restate
   expand) previously stuck across questions; the render-phase reset
   (React's documented "adjust state on prop change" pattern — no
   effect, per the set-state-in-effect lint law) closes that too.
4. **Part jump-row** (same file): when ANY part carries an attested
   printed label, a sticky chip row under the drawer header scrolls the
   drawer to that part (`ms-part-<id>` anchors, scroll-mt-20). Chips
   speak the partDisplayLabel law — never an order number. The row is
   suppressed entirely when no part is labeled (the first build
   rendered an empty nav bar — caught in the local pass, fixed before
   commit).
5. **Contextual CLA prompt chips** (`question-cla-overlay.tsx`): the
   free-input block gained four situational starters — two per live
   mode (EXPLAIN: "Explain what this question is asking" / "Break down
   part (a) for me" — part-phrased when the anchor is a part; HINT:
   "Give me a hint to get started" / "I'm stuck — coach me step by
   step"). A tap PREFILLS the draft and focuses the ask box
   (`askInputRef` — the Input forwards ref under React 19); the send
   stays the learner's deliberate fire. Our law beats MG's auto-send.
   Chips disabled while a turn is in flight; `role="group"
   aria-label="Suggested prompts"`.
