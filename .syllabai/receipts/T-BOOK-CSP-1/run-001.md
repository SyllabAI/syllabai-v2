## The defect (diagnosed live before this run)

The books lesson rail ships TWO cross-origin embed widgets, each with its
own provider law:

- **media-embed** (ADR-BOOK-0002/0003): lesson videos via
  `youtube-nocookie.com` ONLY (rel=0, no autoplay, lazy). Live census on the
  one serving book (Edexcel IGCSE Chemistry Student Book,
  `e6c0db50-0f84-55de-b50c-e4d49285cd6d`): **63 video blocks across all 29
  chapters, 63/63 with `youtubeId` + `licenseRef`** — the data plane is
  complete and correct.
- **sim-embed** (T-BOOK-006): the PhET iframe (`phet.colorado.edu/sims/html/…`,
  consent-to-load) — "PhET is the ONLY provider in the pilot". Live census:
  sim blocks serve in the same book ("States of Matter: Basics", "Build an
  Atom", "Balancing Chemical Equations" in u1:c1–c5 alone).

The CSP's `frame-src` read `'self'` — written when the only frames were the
SAME-ORIGIN KG / graph-explorer builds (the comment block said exactly
that). Both widgets shipped later; the header was never widened. Result in
every real browser: the WATCH / Simulation card renders (title, blurb,
attribution, the plain "Watch on YouTube" link card) and the PLAYER IFRAME
is refused by the browser — the screenshot of record shows the blocked
glyph in the player box
(`download/checks/lesson-video-player.png`, operator session evidence).
The embed URL itself is reachable (200) — only the page policy blocks it.
`frame-src 'self'` is mathematically incapable of allowing a cross-origin
embed, so no amount of data-plane work could ever fix the symptom.
